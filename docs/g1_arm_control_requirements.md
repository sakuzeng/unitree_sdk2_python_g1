# Unitree G1 手臂控制系统需求文档

## 项目概述

### 项目目标
基于 Unitree G1 机器人开发手臂控制系统，实现精确的手臂运动控制和定位，为配合 Dex3 灵巧手执行抓握任务提供基础平台。

### 核心价值
- 提供高精度的手臂运动控制能力
- 实现手臂与灵巧手的协调控制
- 支持复杂的空间轨迹规划和执行
- 为机器人操作任务提供稳定的手臂定位基础

## 功能性需求

### 1. 数据收集与预处理系统

#### 1.1 电机数据采集
- **需求描述**: 收集G1手臂电机的运行数据用于模型训练
- **功能要求**:
    - 实时采集关节电机位置、速度、力矩数据
    - 记录手臂末端位姿与关节角度的对应关系
    - 采集不同运动模式下的数据（慢速、中速、快速）
    - 支持多种运动轨迹的数据收集（直线、曲线、复合运动）
    - 数据时间戳同步和标注
- **技术规格**:
    - 采集频率: 100Hz
    - 数据精度: 位置±0.01°，力矩±0.001Nm
    - 存储格式: CSV/HDF5
    - 单次采集时长: 10-60分钟
- **输入**: 手臂运动指令、传感器数据
- **输出**: 标注数据集、统计报告
- **优先级**: 高
- **实现状态**: 🚧 需要实现 - 当前GUI存在bug，数据采集功能未验证

#### 1.2 数据预处理与标注
- **需求描述**: 对采集的数据进行清洗、标注和预处理
- **功能要求**:
    - 数据去噪和异常值检测
    - 运动意图标注（上、下、左、右、前、后）
    - 数据归一化和特征提取
    - 训练集、验证集、测试集划分
    - 数据增强和平衡处理
- **输入**: 原始采集数据
- **输出**: 预处理后的训练数据集
- **优先级**: 高
- **实现状态**: 📋 计划开发 - 依赖数据采集功能完成

#### 1.3 数据质量评估
- **需求描述**: 评估采集数据的质量和完整性
- **功能要求**:
    - 数据覆盖度分析
    - 信噪比评估
    - 数据分布均匀性检查
    - 标注一致性验证
- **输入**: 预处理数据
- **输出**: 数据质量报告
- **优先级**: 中
- **实现状态**: 📋 计划开发

### 2. 机器学习模型系统

#### 2.1 运动意图识别模型
- **需求描述**: 训练模型识别键盘输入对应的手臂运动意图
- **功能要求**:
    - 支持6个基本运动方向的分类（上、下、左、右、前、后）
    - 实时运动意图预测（<50ms）
    - 模型在线更新和增量学习
    - 支持多种模型架构（SVM、随机森林、神经网络）
- **技术规格**:
    - 分类精度: >95%
    - 推理延迟: <50ms
    - 模型大小: <100MB
    - 支持CPU推理
- **输入**: 电机状态数据、键盘指令
- **输出**: 运动意图分类、置信度
- **优先级**: 高
- **实现状态**: 🚧 部分实现 - 代码中有MLPRegressor引用，但模型训练流程未完成

#### 2.2 运动轨迹生成模型
- **需求描述**: 基于运动意图生成平滑的手臂运动轨迹
- **功能要求**:
    - 从当前位置到目标方向的轨迹生成
    - 考虑关节限制和碰撞避免
    - 支持不同运动速度和幅度
    - 轨迹平滑性优化
- **技术规格**:
    - 轨迹生成时间: <100ms
    - 平滑度: 连续二阶导数
    - 运动精度: ±2mm
- **输入**: 运动意图、当前状态、运动参数
- **输出**: 关节空间轨迹、执行时间
- **优先级**: 高
- **实现状态**: 🚧 需要调试 - 轨迹生成逻辑存在问题

#### 2.3 模型训练与优化
- **需求描述**: 实现模型的训练、验证和优化流程
- **功能要求**:
    - 自动化训练管道
    - 超参数优化
    - 交叉验证和性能评估
    - 模型版本管理
    - 在线学习和适应
- **输入**: 训练数据、模型配置
- **输出**: 训练好的模型、性能报告
- **优先级**: 中
- **实现状态**: 📋 未开始 - 需要完整重新设计

### 3. 键盘控制系统

#### 3.1 键盘输入处理
- **需求描述**: 实现键盘输入的实时处理和解析
- **功能要求**:
    - 支持方向键控制（↑:up, ↓:down, ←:left, →:right）
    - 支持WASD/QE控制（W:前, S:后, A:左, D:右, Q:上, E:下）
    - 支持F/B键控制（F:forward, B:back）
    - 按键持续时间检测
    - 紧急停止键（ESC/空格）
    - 速度调节键（Shift加速）
- **技术规格**:
    - 输入延迟: <10ms
    - 按键检测精度: >99%
    - 支持键盘重复按键
- **输入**: 键盘按键事件
- **输出**: 运动控制指令
- **优先级**: 高
- **实现状态**: 🚧 存在bug - Qt事件过滤器实现有问题，键盘输入不稳定

#### 3.2 运动控制映射
- **需求描述**: 将键盘输入映射为手臂运动控制指令
- **功能要求**:
    - 可配置的按键映射关系
    - 运动方向和幅度控制
    - 渐进式运动控制（基于推理的平滑运动）
    - 运动速度实时调节
    - 左右手臂切换支持
- **输入**: 键盘控制指令
- **输出**: 手臂运动参数
- **优先级**: 高
- **实现状态**: 🚧 需要重构 - 映射逻辑不完整，存在运行时错误

#### 3.3 用户界面与反馈
- **需求描述**: 提供直观的控制界面和状态反馈
- **功能要求**:
    - 实时显示手臂当前位置和状态
    - 键盘控制说明和帮助
    - 按键视觉反馈覆盖层
    - 安全状态指示
    - 操作历史记录
- **输入**: 系统状态、用户操作
- **输出**: 可视化界面、状态信息
- **优先级**: 中
- **实现状态**: 🚧 部分实现 - 界面框架存在，但功能不完整

### 4. G1手臂基础控制系统

#### 4.1 关节级控制
- **需求描述**: 实现G1手臂6自由度关节的精确控制
- **功能要求**:
    - 支持左右手臂独立控制（12个关节：肩膀3DOF + 肘部1DOF + 腕部2DOF × 2）
    - 实现位置控制、速度控制和力矩控制模式
    - 提供关节角度、角速度和力矩反馈
    - 支持关节空间和任务空间控制切换
- **技术规格**:
    - 控制频率: 50Hz（目标100Hz）
    - 位置精度: ±0.1°
    - 力矩精度: ±0.05Nm
    - 响应时间: <20ms
- **输入**: 关节角度命令、力矩命令、速度命令
- **输出**: 关节状态、力反馈、位置反馈
- **优先级**: 高
- **实现状态**: ❌ 存在严重问题 - DDS通信不稳定，关节控制指令发送失败

#### 4.2 正逆运动学计算
- **需求描述**: 实现手臂正逆运动学求解
- **功能要求**:
    - 正运动学：关节角度 → 末端执行器位姿
    - 逆运动学：目标位姿 → 关节角度组合
    - 支持多解选择和奇异性避免
    - 实时运动学计算（<5ms）
- **技术规格**:
    - 计算精度: 位置±1mm，姿态±1°
    - 计算延迟: <5ms
    - 奇异性检测和避免
- **输入**: 关节角度或目标位姿
- **输出**: 末端位姿或关节角度解
- **优先级**: 高
- **实现状态**: 📋 未实现 - 需要集成专业运动学库（如robotics-toolbox）

#### 4.3 安全保护机制
- **需求描述**: 确保手臂运动安全性
- **功能要求**:
    - 关节角度软硬限位保护
    - 关节速度和加速度限制
    - 力矩过载保护和监控
    - 碰撞检测和紧急停止
    - 奇异性位置避免
    - 键盘控制模式下的额外安全检查
- **安全规格**:
    - 紧急停止响应时间: <50ms
    - 碰撞检测响应时间: <100ms
    - 关节角度安全范围监控
    - 最大角速度限制: 0.3 rad/s（键盘控制模式）
    - 减小控制增益确保平滑运动（kp=40.0, kd=1.0）
- **输入**: 传感器数据、安全参数、实时状态
- **输出**: 安全状态、报警信息、保护动作
- **优先级**: 高
- **实现状态**: 🚧 基础框架 - 卸力功能代码存在，但安全检查逻辑不完整

### 5. 轨迹规划与执行系统

#### 5.1 实时轨迹生成
- **需求描述**: 基于键盘输入实时生成手臂运动轨迹
- **功能要求**:
    - 在线轨迹生成和修正
    - 平滑的运动轨迹插值
    - 支持运动中途修改目标
    - 避免突变和震荡
- **技术规格**:
    - 轨迹更新频率: 50Hz
    - 轨迹平滑度: 连续二阶导数
    - 生成延迟: <20ms
    - 步长: 0.008 rad（确保平滑运动）
- **输入**: 键盘控制指令、当前状态
- **输出**: 实时运动轨迹
- **优先级**: 高
- **实现状态**: ❌ 存在问题 - 轨迹生成算法不稳定，容易产生异常运动

#### 5.2 运动执行与监控
- **需求描述**: 执行生成的运动轨迹并监控执行状态
- **功能要求**:
    - 实时轨迹跟踪控制
    - 执行误差检测和补偿
    - 运动状态实时监控
    - 异常情况处理
- **输入**: 目标轨迹、实时反馈
- **输出**: 控制指令、执行状态
- **优先级**: 高
- **实现状态**: ❌ 需要重写 - 轨迹跟踪控制器存在严重bug
